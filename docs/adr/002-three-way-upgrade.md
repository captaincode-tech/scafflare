# ADR-002: ارتقای امن با merge سه‌طرفه و base ذخیره‌شده

**وضعیت:** پذیرفته‌شده  
**نسخهٔ هدف:** `0.2.0`

## زمینه

lockfile نسخهٔ ۱ فقط hash آخرین محتوایی را نگه می‌داشت که Scafflare نوشته بود. با آن می‌شد فقط تشخیص داد فایلی دست‌خورده است و در این حالت `add`/`remove` متوقف یا محتاط می‌شدند؛ راهی برای دریافت نسخهٔ جدید Recipe بدون از دست دادن تغییرات کاربر وجود نداشت (مثلاً `node` از 0.1.0 به 0.2.0 رسید و پروژه‌های قدیمی فقط خطای version mismatch می‌گرفتند). حتی `npm install <pkg>` که `package.json` را تغییر می‌دهد، دستور `add` را برای همیشه مسدود می‌کرد.

## تصمیم

1. برای هر فایل مدیریت‌شده، render خالصِ بدون تغییر کاربر (*base*) به‌صورت content-addressed در `.scafflare/base/<sha256>` (بدون پسوند، تا ابزارهای TypeScript/Biome/Vitest آن را منبع نپندارند) ذخیره و hash آن در lockfile نسخهٔ ۲ ثبت می‌شود. `sha256` جداگانه محتوای روی دیسک را برای تشخیص drift نگه می‌دارد.
2. `upgrade` و `add` از یک موتور واحد `reconcile` استفاده می‌کنند که B/O/T را قاعده‌به‌قاعده تطبیق می‌دهد (جدول در docs/architecture.md). JSON با merge ساختاری و متن با diff3 (`diffy`) merge می‌شود؛ آرایه‌ها اتمی‌اند.
3. پیش‌فرض در conflict **abort** است: تحلیل کامل پیش از نوشتن انجام می‌شود و هیچ فایلی تغییر نمی‌کند. `--conflicts markers` markerهای متنی یا فایل کناری `.scafflare-new` می‌نویسد و base را به نسخهٔ جدید می‌برد تا پس از حل دستی، تغییر دوباره conflict نشود؛ تا حل‌نشدن، `upgrade`/`add` رد می‌شوند.
4. ترتیب commit: فایل‌ها، baseهای جدید، lockfile، سپس حذف baseهای بی‌مصرف تا قطع شدن میانهٔ کار قابل بازیابی باشد.
5. `remove` همان رفتار محافظه‌کارانه را حفظ می‌کند و فقط در پروژهٔ به‌روز اجرا می‌شود.
6. lockfileهای نسخهٔ ۱ خوانده و در حافظه migrate می‌شوند. فایل بدون base فقط اگر hash آن با `sha256` ثبت‌شده برابر باشد fast-forward می‌شود؛ JSON به‌صورت افزایشی merge می‌شود و متن conflict گزارش می‌کند.
7. ورودی‌های lockfile (مسیرها و hashها) هنگام بارگذاری اعتبارسنجی می‌شوند و baseها پیش از استفاده با hash تأیید می‌شوند؛ base خراب یا گم‌شده به حالت «بدون base» تنزل می‌کند، نه crash.

## پیامدها

- مصرف دیسک اندکی بیشتر (یک نسخه از render هر فایل) و breaking برای 0.1.x: lockfile نسخهٔ ۲ توسط 0.1 رد می‌شود.
- هر تغییر محتوای Recipe باید نسخه‌اش را بالا ببرد؛ این قاعده با `recipes/official/CHECKSUMS` در CI اجرا می‌شود.
- merge متنی خطی است؛ تغییر هم‌زمان یک خط، conflict می‌سازد. YAML/TOML و upgrade تک‌Recipe خارج از scope هستند.
- حداقل نسخهٔ Rust برای انطباق با وابستگی‌های قفل‌شده به 1.85 رسید.
